# MOB-033 — Instructor formation overview

## Superseded behavior (2026-10-16)

Formation follow-up previously had no single searchable instructor overview.
Some screens also relied on broad formation snapshot reads, which could expose
career, theory, MIL, goals, or notes to a pool-only instructor, and an absent
target brevet could be replaced by an inferred target in the inline summary.
That behavior is superseded.

## DEV behavior

- Canonical app administrators (`app_role`) and LIFRAS validators may use the
  full formation overview. A legacy club statute label alone does not grant
  access, matching the server and Firestore authorization gates.
- Pool-only instructors use `getPoolFormationOverviewV1` and a deliberately
  reduced DTO/projection. It contains pool identity and progress only; it does
  not include career, theory, MIL, goals, dive details, or private member data.
- Firestore rules deny pool-only instructors direct reads of full formation
  snapshots, formation goals, tasks, and non-pool observations.
- Pool remarks are limited to dated pool-session context and remain distinct
  from LIFRAS exercise validation.
- A successful pool-remark write is never reported as failed merely because
  the post-write list refresh is temporarily unavailable, preventing duplicate
  retries.
- Missing or denied data fails closed with a visible load error.
- The inline MIL requirements card shows requirements only when an explicit
  target brevet exists; it never invents a target.

## Verification

Automated coverage includes permission scopes, full and pool-only Firestore
read boundaries, the callable's reduced projection, error states, target-level
requirements, and the no-inferred-target case. Manual DEV testing should use
separate administrator/validator, pool-only instructor, and ordinary-member
accounts and confirm that each sees only its authorized view.

No production rules or function deployment, app build, or store release is
part of this DEV merge.

## CALYMOB-23 follow-up (2026-10-18)

The previous mobile behavior that started an operation-wide observation
listener for every activity viewer is **superseded**. CalyMob now mirrors the
full-formation read gate before requesting other members' observations;
ordinary members request only their own authorized observations. Club-wide
participant decoration uses `member_directory`, never private `members`.
Affected realtime listeners own their lifecycle and surface a small retryable
French error instead of allowing `permission-denied` to escape as an unhandled
exception. The MOB-033 Firestore privacy boundary itself is unchanged.
