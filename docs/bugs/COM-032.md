# COM-032 — 3★-oefeningen ontbraken bij inschrijving voor een uitstap

## Intake

- Ticket: COM-032
- App: CalyMob
- Prioriteit: gênant
- Gemeld op: 2026-04-04
- Bewijs: WhatsApp-screenshot bij het ticket
- Scenario: een actieve 2★-duiker schreef zich in voor La Croisette en zag geen
  oefeningen voor de opleiding tot 3★
- Classificatie: functionele bug, reeds gecorrigeerd en uitgebracht

## Reproductie vóór de correctie

1. Meld aan als lid met `plongeur_code: 2`.
2. Open een clubuitstap en start de inschrijving/oefeningselectie.
3. CalyMob berekent terecht doelniveau `P3`.
4. `getExercicesByNiveau(P3)` voerde toen een Firestorequery uit met `where(niveau)
   + orderBy(code)`.
5. Door de ontbrekende samengestelde index faalde de query; de service ving de
   fout af en retourneerde een lege lijst.

Verwacht: P3-oefeningen en oefeningen “Tous Niveaux” zijn selecteerbaar.

Werkelijk vóór de fix: geen oefeningen zichtbaar, zonder bruikbare foutmelding.

## Oorzaak

De oefencatalogus was aanwezig, maar de mobiele service maakte de leesbaarheid
afhankelijk van een samengestelde Firestore-index. De catch zette zowel “query
faalde” als “geen oefeningen” om in dezelfde lege lijst. Daardoor leek het alsof
P3-data ontbrak.

## Correctie op `main`

Commit `d3b599c` (`fix: resolve missing LIFRAS exercises for all niveaux`) wijzigde
de service op 4 april 2026:

- laad de volledige, op code gesorteerde oefencatalogus met één geldige query;
- filter lokaal op het berekende doelniveau;
- voeg altijd `TN`-oefeningen toe;
- accepteer via het model zowel canonieke `P3`- als numerieke niveauvormen;
- sorteer het resultaat deterministisch op code.

De activiteitdetailflow berekent voor `plongeur_code: 2` het doelniveau `P3` en
vraagt exact die lijst op. De correctie zit in actuele `origin/main` en is aantoonbaar
opgenomen in de uitgebrachte tag `v1.9.12` (latere versies erven de commit).
