# MOB-052 — configurable text thread colours (DEV only)

The old product parser and order customization calculator discarded thread
colour. Products can now provide `embroidery.name.allowedColors` and
`embroidery.certification.allowedColors` (up to16 plain labels of40 characters),
independently per article. These are not garment variant colours. Club-logo
colours do not become buyer-selectable. Existing `color` remains the fixed or
default label. An absent buyer colour uses the configured default, or the first
palette entry, so older clients remain compatible. Palette changes do not
rewrite old orders. Unknown buyer colours and malformed configuration fail
closed. Colours never alter personalization pricing.

The real product screen, basket payload/key, persisted order snapshots, order
history and payment description retain the canonical label. CalyCompta's
companion change configures palettes and displays saved colours on order and
production labels. Size amendments preserve the stored customization snapshot.

Fictional DEV scenario: `?scenario=thread-colors` on the credentialless isolated
DEV target. The basket is memory-only, no FirebaseAuth or storage is started.
Regression coverage includes real product selection, save/reopen, fixed legacy
colour, invalid/stale colour, unchanged price, order transaction and snapshot.

This feature is NOT in the already-running536 Cloud build from d20bcd3.
It needs a later separately authorized app build and backend publication.
This ticket's current authorization covers DEV only, not production.
