# MOB-038 / MOB-040 — badge and destination-list parity

Status: implemented for DEV on 2026-10-16.

## Problem

- MOB-038: an event conversation could contribute to the home badge after its
  event disappeared from the default event list.
- MOB-040: the Communication badge was loaded as an aggregate while the hub
  rebuilt its row streams and count futures independently. A slow first pool
  snapshot could therefore leave the hub spinning even though the home badge
  was non-zero.

## Current contract

- A cursor refresh is still all-or-nothing and bounded by the existing
  eight-second Firestore query timeout.
- The successful cursor snapshot retains totals plus per-event, per-team and
  per-session counts. Home badges and destination rows read that same snapshot.
- A failed refresh does not replace the previous complete snapshot with
  partial zeros.
- Team and pool list streams are stable for the lifetime of their sections.
  Their last successful list remains visible during errors or a retry.
- Cached rows are retained only for retries within the same source. A changed
  team authorization scope clears the old rows immediately and ignores any late
  events from that scope. The inbox is mounted only after the member profile
  matches the authenticated identity and club; switching identity recreates its
  sections. Same-identity profile refreshes use MemberProvider's existing cache.
- Pool rows use the complete cursor snapshot before creating any fallback count
  request, preventing duplicate reads and unobserved failed futures.
- If a list produces neither data nor an error for eight seconds, the UI shows
  a retry action. Event lists follow the same timeout/retry behavior and retain
  their last successful rows.
- A Firestore error in the dedicated `Clôturés` list now shows that same visible
  retry instead of silently rendering an empty-state message.
- Main, past and closed activity subscriptions use generation guards: a late
  callback from a cancelled older subscription cannot overwrite the newer
  list.
- Past closed and cancelled events remain reachable through the explicit
  historical controls; choosing past events resets the category to `Tout`.
- Legacy unread mode keeps its existing per-row query behavior for rollback
  compatibility.

## Verification

- Unit coverage verifies retained-list timeout and retry behavior.
- Provider coverage verifies cursor home totals and row counts use the same
  snapshot.
- Identity-gate widget tests use synthetic member loaders without initializing
  Firebase and verify that foreign profiles cannot start inbox sources. Profile
  retries target the current authenticated member.
- Event-filter coverage verifies past and cancelled-event discoverability.

Local follow-up checks: 30 targeted loader, identity-gate, member-provider,
unread-provider and event-filter tests pass; analysis of the changed Dart files
reports no issues. These checks use synthetic data and in-memory substitutes.
Native/DEV verification and the grouped mobile release remain separate steps.
