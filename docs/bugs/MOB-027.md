# MOB-027 — unread counters match their conversation details

Status: the source fix is already present on `main`. Board resolution and live
device/store acceptance remain separate operational decisions.

## Report evidence

The live report was filed from CalyMob `1.22.3+211` on iOS. Its attachment
shows `99+` on both the **Événements** and **Communication** landing tiles even
though the underlying conversation details did not contain that many unread
messages.

The report's existing diagnosis identifies the historical cause: read state
was stored per device, and an existing installation without a usable local
cursor fell back to 2024. That made the aggregate counter include old history
while a conversation detail could use a different device-local position.

## Existing fix on `main`

Unread cursor v1 replaces that split authority with server-owned, per-member
Firestore cursors:

- announcement, event, team and session counts are derived from the same root
  and scoped `read_state` cursors used when their detail screens acknowledge
  visible content;
- landing-tile, row and app-icon formulas use the canonical cursor breakdown
  instead of treating legacy `unread_counts` or a device cache as authority;
- cursor handover hides the old cached `99+` values until bootstrap and one
  complete canonical query succeed;
- cache and rollback mirrors are namespaced by club and member, so reinstall,
  sign-out and account switching cannot reuse another context's unread state;
- Functions calculate exact recipient badges, including zero, and sender/read
  acknowledgements advance server timestamps rather than client clocks.

The foundational implementation is the canonical `main` phase sequence
`96495c9`, `4572797`, `a628033`, `055030c`, `ffda033` and `0886b17`.
Production-readiness and handover hardening include `45105e4`, `5a96bae`,
`6429be2` and `bac7a2c`, merged to `main` through PRs #88 and #89.

PR #94 (`f53b228` through `d267633`, followed by release PR #95) is related but
separate: it makes a detail open at the first unread message represented by the
captured canonical cursor. It does not constitute the counter fix itself. The
scroll-only history is documented in
[`CHAT_SCROLL_REGRESSION_2026-09-29.md`](./CHAT_SCROLL_REGRESSION_2026-09-29.md).

## Source verification — 2026-10-05

The current `origin/main` candidate was inspected from a clean dedicated
worktree. The aggregate services and detail acknowledgements share the same
canonical section/scope cursor paths for announcements, events, team channels
and session chats.

The focused Flutter suite passed 88 tests across:

- cursor-derived category and conversation counts;
- provider handover, identity isolation and stale-`99+` suppression;
- server-cursor acknowledgement and rollback mirroring;
- landing badge formulas and unread contract fixtures;
- detail divider/index anchoring for the captured pre-open cursor.

Focused analysis of the twelve affected provider/service/screen files reported
no errors or warnings (25 pre-existing informational lints in
`operations_list_screen.dart`). The matching Functions/Jest suite was not
rerun in this worktree because `functions/node_modules` is absent; no dependency
installation was performed for this read-only audit.

No new product code, deployment, production data, feature flag or store state
is changed by this documentation correction.
