# MOB-041 — Multiple screenshots in one CalyMob report

## Delivered behavior

- A reporter can attach up to five screenshots to one report.
- **Ajouter une autre capture** closes the form, retains the title,
  description, priority, and existing screenshots, and re-enables the floating
  capture button for another screen.
- The preview supports removing a screenshot and changing its order.
- Each screenshot retains the NavigatorObserver's current route label (an
  explicit route name when meaningful, otherwise the active screen and visible
  AppBar/tab title) and capture time; uploads use stable
  `screenshot_0.png` through `screenshot_4.png` paths in preview order.
- `screenshotUrl` remains the first attachment URL for legacy readers, while
  `screenshots` contains the complete ordered list.
- The form accepts one submission at a time, including rapid taps received
  before the disabled-button frame is rendered. After a failed submission it
  retains the draft and ordered screenshots and allows a new attempt.

## Submission safety

The unrestricted create-then-update behavior in the older client is
**superseded as of 2026-10-16** by the existing hardened CalyCompta contract:
the client first creates an owned `nouveau` report with no screenshots, uploads
only canonical `screenshot_0.png` through `screenshot_4.png` objects, then makes
one rules-limited update containing only `screenshots` and `screenshotUrl`.
Each attachment records a Firestore timestamp and its storage index. A partial
failure deletes the attempted reporter-owned objects and the still-empty report.
Owner deletion is allowed only while the report remains empty and unfinalized;
finalized evidence and reports remain admin-managed.

## Verification

- Unit/widget coverage checks ordered uploads, the five-image server-side and
  UI bounds, reverse-order cleanup, preservation of the original upload error,
  route labels, retained draft fields, removal/reordering, cancellation, rapid
  send taps, and retry after failure. The 12 targeted tests pass locally with an
  injected synthetic submission service; no Firebase app is initialized for the
  submission tests. Changed-file analysis has no errors or warnings (three
  existing opacity-style info notices remain).
- Firebase emulator coverage in the companion CalyCompta rules change checks
  owner-only upload/finalization/cleanup for both the established JPEG format
  and CalyMob PNG attachments.
- Manual DEV check: capture two different screens, return to the form after
  each capture, verify the draft is retained, reorder/remove an image, submit,
  and confirm both ordered attachments appear in Signalements & Bugs.

No production deployment or store publication is part of this change.
