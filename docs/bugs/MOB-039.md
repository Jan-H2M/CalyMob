# MOB-039 — participant phone access for event staff

Status: implemented for DEV on 2026-10-16.

## Behavior

- The original event creator, current organiser, and members with the exact
  club status `encadrant` or `encadrants` may request a registered member's
  phone from the participant list.
- The lookup is by the registration's exact member ID and reads only the
  consent-filtered `member_directory` projection.
- The phone is shown only when the returned directory document has the same
  member ID, `share_phone` is true, and the number is non-empty.
- Ordinary members, guests, name-only registrations, mismatched IDs and
  revoked consent fail closed. No private-member-document fallback exists.
- Authority and selected-operation identity are checked again after the async
  directory read before showing the dialog.
- Encadrant roles are accepted only from the profile loaded for the current
  authenticated member and club. Account/profile changes rebuild the actions;
  already-rendered callbacks and in-flight lookups also recheck this binding.

## Verification

Widget tests cover an opted-in participant, consent revocation, an ordinary
member, roles cached from another account/club, and loss of profile authority
during a delayed directory lookup. Unauthorized users receive neither a number
nor a new directory lookup. Policy tests cover staff authority, exact-ID
binding, consent, and empty numbers.

The two targeted test files pass all 14 tests. The source analyzer diagnostics
are unchanged from the parent (3 existing warnings and 98 infos); the modified
test file has no diagnostics. Tests use synthetic local mocks only.
