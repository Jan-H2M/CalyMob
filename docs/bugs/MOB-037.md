# MOB-037 — Exercise progress in sortie planning

## Superseded behavior (2026-10-16)

The sortie monitor-planning screen previously showed only the requested
exercise labels and a coarse formation percentage. Registrations could contain
either LIFRAS codes or exercise document IDs, and progress detail could include
rows from a different target brevet. That presentation is superseded.

## DEV behavior

- Requested exercise document IDs are resolved to canonical LIFRAS codes;
  unknown values are counted and shown as a warning instead of exposed as
  opaque identifiers.
- Each participant can expand a read-only **Milieu naturel** panel sourced from
  the same materialized formation snapshot used by the formation views.
- Totals and detail rows apply the same current-target filter, deduplicate codes,
  and preserve the precedence validated > pending > remaining.
- Planning assignments remain intentions only; this change does not validate
  exercises or write progress.

## Verification

Widget/model coverage checks code resolution, unresolved IDs, modality
classification, target-brevet filtering, deduplication, counts, and visible
validated/pending/remaining rows. Manual DEV testing should open a sortie with
participants at different target levels and compare the panel with each
participant's formation snapshot.

No production or store release is part of this change.
